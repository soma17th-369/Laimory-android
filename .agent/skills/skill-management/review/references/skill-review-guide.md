# 스킬 리뷰 가이드

스킬 리뷰는 단순 맞춤법 검사가 아니라, 에이전트가 해당 스킬을 정확한 시점에 찾고 필요한 기준을 빠르게 사용할 수 있는지 확인하는 작업입니다.

## 0. 기본 전제

- 리뷰 대상은 `SKILL.md` 하나가 아니라 스킬 폴더 전체입니다.
- `index.md`, `SKILL.md`, `references/` 문서, 관련 Agent 문서 링크를 함께 확인합니다.
- 공식 Skill 리뷰 기준을 참고하되, 이 저장소의 `.agent` 구조에 맞게 판단합니다.

## 1. 리뷰 순서

1. 스킬의 책임과 사용 시점을 한 문장으로 요약합니다.
2. 폴더 위치가 책임 영역에 맞는지 확인합니다.
3. `SKILL.md` frontmatter의 `name`, `description`이 명확한지 확인합니다.
4. `## 참조` 링크가 실제 파일을 가리키는지 확인합니다.
5. reference 문서가 번호형 제목, 판단 기준, 예시, 예외 처리를 갖췄는지 확인합니다.
6. 기존 문서와 규칙 중복이나 책임 침범이 없는지 확인합니다.
7. 필요한 경우 서브 에이전트로 독립 검토하거나 실제 사용 시나리오로 검증합니다.

## 2. 구조 체크

- 스킬 폴더는 `.agent/skills/<category>/<topic>/` 아래에 둡니다.
- category index에서 하위 스킬로 연결합니다.
- `SKILL.md`의 참조는 Markdown 링크 목록으로 작성합니다.
- reference 문서의 본문 제목은 필요한 경우 `1.`, `1.1` 형식으로 번호화합니다.
- 코드 블록 안의 주석이나 예시 Markdown 제목은 문서 헤딩 규칙 검사 대상에서 제외합니다.

## 3. Description 체크

- 무엇을 하는 스킬인지 드러나야 합니다.
- 어떤 요청이나 작업 상황에서 사용할지 드러나야 합니다.
- 너무 넓은 표현을 피합니다.
- 다른 스킬과 책임이 겹치면 차이를 설명하거나 카테고리를 조정합니다.

## 4. Reference 체크

- reference는 실제로 에이전트가 판단할 때 필요한 내용을 담아야 합니다.
- 추상적 원칙만 있고 예시가 없으면 보완합니다.
- 예외 처리 기준이 없으면 모호한 상황에서 흔들릴 수 있으므로 추가합니다.
- 같은 내용을 다른 reference에 복사하지 말고 원천 문서로 링크합니다.

## 5. 리뷰 리포트 형식

리뷰 결과는 아래 순서로 작성합니다.

```markdown
## 요약
<스킬의 목적, 책임 영역, 전체 판단>

## 치명적 문제
<로드, 링크, 구조, 책임 분리 실패처럼 바로 고쳐야 할 문제. 없으면 "없음.">

## 주요 개선
<품질이나 사용성을 의미 있게 낮추는 문제>

## 제안
<선택 가능한 개선 또는 정리 아이디어>

## 잘된 점
<유지해야 할 좋은 구조나 기준>
```

## 6. 서브 에이전트 활용 기준

- 스킬 변경 범위가 크거나, 실제 트리거/사용성이 애매하면 독립 검토용 서브 에이전트를 사용합니다.
- 서브 에이전트에는 내가 내린 결론을 넘기지 않고, 검토 대상 파일과 요청만 전달합니다.
- 의도한 정답이나 수정 방향을 알려주지 않습니다.
- 결과가 내 판단과 다르면 원문을 다시 확인하고 필요한 경우 문서를 조정합니다.

## 7. 피해야 할 리뷰

- `SKILL.md`만 읽고 스킬 전체를 판단하는 리뷰
- 취향을 구조적 결함처럼 말하는 리뷰
- 링크 검증 없이 참조 구조가 맞다고 판단하는 리뷰
- 공식 Skill 기준을 이 저장소에 그대로 강제하는 리뷰
