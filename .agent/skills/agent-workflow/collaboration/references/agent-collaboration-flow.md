# Agent 협업 플로우 가이드

이 문서는 Codex와 Claude가 같은 이슈를 처리할 때의 기본 핸드오프 순서를 정의합니다.

## 1. 기본 흐름

| 단계 | 작업 | 담당 | 목적 |
|---|---|---|---|
| 1 | 기획 | Codex | 요구사항, 범위, 산출물, 검증 기준을 정리 |
| 2 | 기획 리뷰 | Claude | 구현 관점에서 기획의 누락, 모호함, 위험을 검토 |
| 3 | 기획 리뷰 반영 | Codex | Claude 리뷰를 반영해 기획과 작업 범위를 확정 |
| 4 | 구현 | Claude | 확정된 기획에 따라 코드와 문서를 변경 |
| 5 | 구현 리뷰 | Codex | 변경사항의 정확성, 회귀 위험, 규칙 위반을 검토 |
| 6 | 구현 리뷰 반영 | Claude | Codex 리뷰를 반영해 구현을 수정하고 검증 |

## 2. 1단계: 기획

Codex가 담당합니다.

- 사용자 요청을 이슈/작업 단위로 정리합니다.
- 작업 범위, 제외 범위, 완료 조건을 명확히 합니다.
- 필요한 경우 Epic과 Task를 나눕니다.
- 새 제품/도메인 용어가 나오면 Ubiquitous Language 검토 필요성을 판단합니다.
- 구현에 필요한 Android, Git, GitHub, Design, Agent 스킬을 식별합니다.

산출물:
- 기획 요약
- 작업 범위
- 완료 조건
- 서브 이슈 후보
- Claude가 리뷰할 질문 또는 리스크

## 3. 2단계: 기획 리뷰

Claude가 담당합니다.

- 구현 가능성과 누락된 세부사항을 검토합니다.
- Android 아키텍처, 모듈, API, UI 상태, Hilt, Navigation 관점에서 위험을 찾습니다.
- 계획이 너무 크면 더 작은 구현 단위로 나눌 것을 제안합니다.
- 요구사항이 모호하면 Codex가 다시 정리해야 할 질문을 남깁니다.

산출물:
- 수용 가능한 계획 항목
- 보완이 필요한 항목
- 구현 전에 확정해야 할 질문
- 예상 구현 리스크

## 4. 3단계: 기획 리뷰 반영

Codex가 담당합니다.

- Claude의 기획 리뷰를 반영해 계획을 수정합니다.
- 사용자의 추가 확인이 필요한 항목을 정리합니다.
- 작업 범위와 완료 조건을 최종화합니다.
- 필요한 GitHub 이슈, Epic, sub-issue를 생성하거나 갱신합니다.

산출물:
- 확정된 구현 계획
- 확정된 이슈 구조
- Claude가 구현할 수 있는 작업 지시

## 5. 4단계: 구현

Claude가 담당합니다.

- 확정된 계획과 `.agent/skills` 규칙에 따라 코드와 문서를 변경합니다.
- 임의로 기획 범위를 확장하지 않습니다.
- 새 도메인 용어를 임의로 만들지 않습니다.
- 필요한 빌드, 테스트, lint, ktlint 검증을 실행합니다.

산출물:
- 코드/문서 변경
- 실행한 검증 명령과 결과
- 구현 중 발견한 추가 리스크

## 6. 5단계: 구현 리뷰

Codex가 담당합니다.

- 변경사항이 확정된 기획과 일치하는지 확인합니다.
- 버그, 회귀 위험, 아키텍처 위반, 누락된 테스트를 우선 검토합니다.
- Git, GitHub, Android, Ubiquitous Language 규칙 위반 여부를 확인합니다.
- 리뷰 결과는 수정이 필요한 항목과 근거 중심으로 정리합니다.

산출물:
- 구현 리뷰 결과
- 수정 요청 항목
- 추가 검증 요청
- 수용 가능한 변경사항

## 7. 6단계: 구현 리뷰 반영

Claude가 담당합니다.

- Codex의 구현 리뷰를 반영해 코드와 문서를 수정합니다.
- 수정한 항목별로 어떤 리뷰를 반영했는지 정리합니다.
- 필요한 검증을 다시 실행합니다.
- 반영하지 않는 리뷰가 있으면 이유를 명확히 남깁니다.

산출물:
- 리뷰 반영 커밋 또는 변경사항
- 재검증 결과
- 남은 이슈 또는 후속 작업

## 8. 예외 처리

- 사용자가 특정 Agent에게 직접 구현이나 리뷰를 요청하면 최신 사용자 요청을 우선합니다.
- 작은 문서 변경처럼 기획 리뷰가 과한 작업은 2-3단계를 생략할 수 있습니다.
- 긴급 버그 수정은 기획 단계를 축약할 수 있지만, 구현 리뷰와 반영은 유지합니다.
- 단계 생략 시에는 왜 생략했는지 작업 기록에 남깁니다.
