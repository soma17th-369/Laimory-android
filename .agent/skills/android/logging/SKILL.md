# Android 로깅 기준

로그는 `core:util` 의 `Logger` 로 남깁니다. `android.util.Log` 를 직접 쓰지 않습니다.

**언제 참조하나요:**
- 새 로그를 적을 때 — 레벨·도메인·문장을 고를 때
- 크래시 리포트 커스텀 키를 추가할 때
- 로그가 섞인 변경을 리뷰할 때

## 1. 한 줄이 가는 곳은 둘이다

| 출구 | 게이트 | 비고 |
| --- | --- | --- |
| Logcat | `Logger.minLevel` | 빌드 타입별 `APP_LOG_LEVEL`. release 는 `WARN` |
| 원격 브레드크럼 | `Logger.remoteMinLevel` | 세 빌드 모두 `INFO`. 수집이 켜진 빌드에서 **기기를 떠난다** |

**`INFO` 이상은 외부로 나가는 문장**이라는 전제로 적습니다. Logcat 하한이 높은 release 에서도 원격으로는 나갑니다.

## 2. 레벨이 곧 정책이다

| 레벨 | 뜻 | 어디로 |
| --- | --- | --- |
| `VERBOSE` · `DEBUG` | 개발용 상세 | Logcat 만 |
| `INFO` | 무슨 일이 있었나 | 브레드크럼 |
| `WARN` | 다뤘지만 이상한 것 | 브레드크럼 |
| `ERROR` + throwable | 몰랐던 실패 | 브레드크럼 + **non-fatal** |

- 사용자에게 안내했거나 재시도로 넘어가는 실패는 "다룬" 실패입니다. `WARN` 이하로 둡니다.
- `ERROR` 에 throwable 을 넘겨도 `Logger.isUnexpectedFailure` 를 통과한 것만 non-fatal 이 됩니다. 서버가 알려 준 오류·통신 끊김·취소는 걸러지지만, 그런 실패라면 애초에 `WARN` 이 맞습니다.

## 3. 원격으로 올라가는 시점

브레드크럼과 커스텀 키는 **크래시나 non-fatal 이 생길 때만** 함께 올라갑니다. 단독으로는 콘솔에 나타나지 않습니다.

- `WARN` 은 "나중에 생길 리포트의 맥락"이고, release Logcat 에서 `adb` 로 바로 보입니다.
- 콘솔에 단독으로 떠야 하는 실패라면 non-fatal 이어야 합니다. 그 전에 정상 경로와 구분되는지부터 봅니다 — 구분되지 않으면 잡음이 진짜 신호를 덮습니다.

## 4. "안 일어난 일"은 짝으로 잡는다

실행되지 않은 코드는 로그를 남길 수 없습니다. 앱 밖(브라우저·시스템·서버 푸시)을 거쳐 돌아와야 하는 흐름은 레벨을 아무리 잘 골라도 실패가 보이지 않습니다.

- 시작을 `INFO` 로 남깁니다.
- 끝(콜백·완료 신호)을 `INFO` 로 남깁니다.
- **시작만 있고 끝 없이 다음 관찰 시점이 오면** `WARN` 으로 남깁니다. 관찰 시점은 보통 앱이 전경으로 돌아오는 순간입니다.

예: 소셜 로그인 — 인증 페이지를 연다 / 콜백을 받는다 / 콜백 없이 앱으로 돌아온다. App Link 가 검증되지 않으면 브라우저가 앱 대신 웹페이지를 열어, 앱은 콜백 인텐트를 아예 받지 못합니다. 세 번째 줄이 없으면 이 실패는 아무 흔적도 남기지 않습니다.

## 5. 브레드크럼과 커스텀 키는 쓰임이 다르다

| | 브레드크럼 | 커스텀 키 |
| --- | --- | --- |
| 담는 것 | 최근에 일어난 일의 순서 | 크래시 시점의 상태 스냅샷 |
| 한도 | 최근 64KB 롤링 | 64개 |
| 적는 곳 | `Logger.i` · `Logger.w` … | `Logger.setCrashKey` |

- **크래시보다 한참 앞서 배경에서 시작된 상태**는 키로 둡니다(위치 수집, 수면 감지 구독, 알림 접근, 초안 작업). 로그로 남기면 크래시 시점에는 이미 창 밖으로 밀려나 있습니다.
- 키 값은 **고정된 몇 개의 토큰**만 씁니다(`on` · `off` · `no_permission`). 식별자·날짜·시각·좌표를 넣지 않습니다.
- 키 이름은 app 모듈의 `CrashKey` 한 곳에 모읍니다. 새 키는 "리포트를 좁히는가, 배경 상태인가" 둘 중 하나일 때만 더합니다.
- 화면 경로는 이미 `route` 키가 잡습니다. 화면 진입·이탈 로그는 두지 않습니다.

## 6. 어디에 무엇을 남기나

| 자리 | 무엇을 | 레벨 |
| --- | --- | --- |
| `ApiCallLogInterceptor` | 모든 Retrofit 요청의 메서드·**경로 템플릿**·HTTP 코드 | 2xx `INFO`, 그 외·통신 실패 `WARN` |
| `safeApiCall` | 응답 봉투의 헤더 코드 실패, 응답 해석 실패 | `WARN` |
| 인증(`LogDomain.AUTH`) | 4번의 시작·끝 짝 | `INFO` / `WARN` |
| 사용자 행동(`LogDomain.USER_ACTION`) | 확정한 행동 한 줄 | `INFO` |
| 배경 상태 | 커스텀 키 | — |

**경로는 템플릿으로 남깁니다**(`timeline/daily-records/{recordDate}`). 실제 URL 에는 기록 날짜·작업·이벤트 식별자가 들어갑니다. 경로를 인터셉터에서 남기는 이유는, 통신이 끊기거나 응답을 해석하지 못하면 `safeApiCall` 은 요청을 볼 수 없고 예외만 받기 때문입니다.

**사용자 행동의 범위**는 "확인 버튼·다이얼로그로 확정하는, 서버나 기기 상태를 바꾸는 행동" 입니다.

- 남김: 초안 생성, 기록 저장·완료, 기록·이벤트·사진 삭제, 이벤트 추가·수정 저장, 약관·단계 동의 제출, 탈퇴·로그아웃, 온보딩 완료, 수면 수동 입력 저장, 수집 켜기·끄기
- 뺌: 화면 이동, 메모·감정처럼 자주 일어나는 편집, 테마·날짜 선택
- **요청 시점에 한 줄**만 남깁니다. 결과는 이어지는 API 로그가 말합니다. API 를 거치지 않는 결과만 따로 남깁니다.
- 여러 화면에서 같은 값을 바꾸는 행동(수집 켜기·끄기)은 그 값을 쓰는 **한 자리**(Repository 구현)에서 남깁니다.

## 7. 남기지 않는 것

- 기록 본문·메모·감정
- 사진 URI·파일 경로·좌표·주소
- 알림·일정의 제목과 내용
- 토큰·FID 원문·이메일·닉네임·회원 식별자
- 요청 URL 원문·쿼리·헤더·본문, 서버가 준 메시지 문자열
- **예외 메시지** — 문장에는 `${e::class.simpleName}` 만 적습니다. 안드로이드 예외 메시지에는 파일 경로·content URI·계정 이름이 들어 있습니다. throwable 인자는 `Logger` 가 `RedactedThrowable` 로 걷어서 내보냅니다.
- 객체 전체(`$state`, data class 의 `toString`)

## 8. 반복 루프 안에 찍지 않는다

위치 샘플·사진 행·알림 수신처럼 자주 도는 자리에서 한 건마다 찍으면, 64KB 창을 통째로 밀어내 정작 중요한 앞부분이 사라집니다.

- 한 묶음을 도는 루프는 루프 밖에서 **집계 한 줄**로 남깁니다(`실패 3건/120건`).
- 계속 반복될 수 있는 실패는 **상태가 바뀔 때만** 남깁니다(처음 실패, 회복).
- 분 단위 폴링처럼 주기가 긴 반복은 한 번에 한 줄이어도 됩니다.

## 9. 도메인 계층에는 로거가 없다

`core:domain` 은 순수 JVM(`kotlin("jvm")`) 모듈이라 `android.util.Log` 에 기대는 `Logger` 를 쓸 수 없습니다. 그래서 `LogDomain` 에 UseCase 영역이 없습니다.

- UseCase 의 결과는 그것을 부른 쪽(ViewModel·app 계층)이 남깁니다.
- 도메인 로그가 실제로 필요해지면, 로거를 순수 JVM 모듈로 옮기고 `android.util.Log` 출력만 포트로 빼는 쪽을 먼저 봅니다. 도메인에 우회 경로를 따로 두지 않습니다.

## 10. `LogDomain`

| 영역 | 쓰는 곳 |
| --- | --- |
| `MVI` | `BaseMviViewModel` 의 Intent 처리·실패 |
| `NAVIGATION` | 내비게이션 호스트의 경로 판정 |
| `NETWORK` | API 요청 결과, 응답 봉투 실패 |
| `REPOSITORY` | 로컬 저장소 읽기·쓰기 실패 |
| `COLLECTION` | 수집기·수집 서비스 |
| `DRAFT_TASK` | 초안 작업 추적 |
| `PUSH` | FCM 수신·등록 |
| `AUTH` | 앱 밖을 거쳐 돌아오는 인증 흐름 |
| `USER_ACTION` | 사용자가 확정한 행동 |
